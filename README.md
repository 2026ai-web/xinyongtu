# 新龙图 Edge 侧栏

v0.12.15 测试包按三层目标采集：数据概况表格合计行、数据明细中每条链接的整体数据、每条链接24小时分时。选择店铺备注和 1/7/30 个完整日，支持暂停续采；三层齐全且校验通过才完成。不再把今日快照作为本任务目标。本机保存，不改投放，不读取登录凭据。

Windows 用户解压发布整包后双击 `install.cmd`。安装器自动写入固定目录并创建桌面更新入口，首次在 Edge 中加载该固定目录。以后双击桌面“新龙图更新”，完成后在 Edge 点重新加载。旧插件停用保留，不自动迁移旧扩展数据。

源码在 `edge-extension/`，安装器在 `windows-installer/`。原单页工具在更多设置中。安装器用 PowerShell 测试核心文件操作；Windows 快捷方式和 Edge 首次安装尚未实机验证。

浏览器测试需 Python Playwright 与 `/usr/bin/chromium`。夹具覆盖真实 DOM 解析、日期回读、24 小时数据、IndexedDB 排他锁与重载保留，以及驱动和编排完整集成；不是已登录拼多多后台验证。

使用和限制见 `edge-extension/使用说明.txt`。若后台控件不兼容，自动暂停并保留诊断，不能将暂停任务当作完整报表。当前不支持文件导入、利润核算或自动调价。

构建脚本只打包固定扩展文件清单，不包含测试、商家数据或环境文件。公开发布使用独立制品分支，保留主分支。

## v0.12.15 测试包

修复主日期与对比日期相互干扰，详情直达链接按目标日重建起止日期。整体指标单独读取并与账户分时核对，链接日整体数据随链接分时保存；单条失败继续其他链接，最终报告未完成及各条失败原因。旧 v0.12.1 任务保留，首次使用新采集协议会重采目标日，不把缺少整体指标的旧断点当完成。

导出 `account-day.summary` 为概况表格合计指标，`account-day.products` 为链接整体明细，`unit-day.dailyOverall` 为对应链接整体数据，`unit-day.hourly` 为24小时数据。`job.coverage` 为覆盖计数；`phase=complete` 才是完整任务。平台未提供的托管花费仍为空且列出未归属差额，不分摊、不补零。

测试安装：下载 `xinyongtu-edge-sidebar-0.12.15.zip` 并解压，优先加载其中 `xinyongtu-edge-sidebar/` 进行测试；保留旧扩展与数据并先停用旧扩展。若通过整包 `install.cmd` 更新固定目录，之后在 Edge 扩展页点重新加载。不要点桌面“新龙图更新”：线上更新通道尚未发布此测试包。此版本仍需用户真实后台验证，离线夹具不等于实际店铺验收。


v0.12.15：滚动不再依赖当前已出现的商品行；遍历文档根、内部纵向容器、横向表格及滚动后新增的懒加载区域，验证实际位移，结束后等待页面稳定并再次检查。滚动期间累计整体指标，支持金额拆分节点、直接文本和当前值后的对比说明；诊断保留滚动位置及整体指标候选识别状态。完整性仍依据链接总数和24小时校验，滚到底不等于采全。


v0.12.15 按用户确认的口径：第一层是“数据概况”表格中实际显示的合计行，不是数字卡片，也不是小时/商品求和。`account-day.summarySources` 标注 `overview-table-total`；缺少、重复或不一致的概况合计阻止完成。商品明细合计只作独立诊断，不冒充概况合计。概况表的24条小时记录不用于链接分页计数。表头/表体/合计行分表时，仅在明确共享的 anq/ant/rc 表格容器内按唯一列签名匹配。加载中的标签可通过已渲染报表验证继续，相同目标URL不重复导航；仍校验日期、页面加载标记及稳定性，最多等30秒。滚动范围排除通知、店铺名、商品名称等省略文字区域。


v0.12.15 记录托管共享关系：账户/托管组/单链接/逐小时数据分层，统计日期与采集时间分开。托管详情经表头证实没有花费列时，保存24小时其他指标并给花费添加not-provided/null；不把缺失记零，稳定推广或其他字段缺失仍阻止完成。托管共享花费在managedShared单独保存，不分摊到链接；差额按用户确认的共享模式规则归类，明确标记derived，保留账户总额与已知链接花费作为计算依据。共享限额/目标投产具体值尚未采集，settings标为not-collected，不能推测。导出含recordingGuide，字段口径见DATA_RECORDING.md。新协议three-layer-table-2会重采当前任务，不删除旧jobs。


v0.12.15 日期修复：保留昨天/近7/近30完整日，增加指定单日、自选起止日期（最多30天）。区间拆为单日任务，开始日=结束日；同一链接每一天单独保存。readonly范围控件通过mousedown/focus打开，明确选开始/结束（单日也选同一天两次）、确认后回读；不直接改写框架文本输入，不修改对比日期。详情链接即使URL带单日但页面残留区间，也重新选择单日后校验。日历打不开、目标日期不唯一/禁用、确认不生效都会停止，不将区间汇总写到某一天。续采按完整日期列表匹配，协议three-layer-table-3。日期操作诊断包含阶段、请求/回读日期、控件和日历信息。


v0.12.15 日期操作与地址保护：仅在工具自己正在选择日期时，允许同站点、同报表路径、同推广身份和同非日期筛选下的beginDate/endDate更新；允许值限制在操作前已验证的日期与本次目标日内。其它参数、路径、身份、hash或操作外地址变化仍暂停。成功前同时核对页面主日期和地址日期（若有）都是目标单日。新增url-guard前后日期/身份及参数名诊断，不导出未知参数值。日期动作不再重复解析整表，点击/渲染耗时与日期解析耗时分开记录；250ms保护未放宽。


v0.12.15 采集性能优化：去掉仅重复验证的稳定等待；导航已获得稳定快照时，短时间内先重新读取并比对同一页面/阶段的数据，变化时回退完整稳定检查。单链接已实际收齐24小时、合计及已识别列时，可跳过无增量的纵向遍历，横向列扫描及最终核对保留；虚拟列表未收齐不走此路径。只读请求缺回执最多重试，日期动作丢回执重入日期状态机回读，不盲重放；滚动等其它动作缺回执仍停止，错误不再武断要求更新插件。job.performance记录本次驱动尝试的耗时、脚本/整表读取和恢复次数，不等于旧任务创建以来累计运行时间。

## v0.12.15 GPT精简导出

新增“GPT精简导出（最近任务）”，按当前店铺备注读取最近保存的任务，刷新侧栏后也可导出，无需重新采集。导出范围看任务自身日期，不根据当前日期下拉框重标历史数据；按钮状态会显示导出的日期。只下载本地JSON，不调用GPT或联网发送。原“完整导出（备份与诊断）”保留全仓库及诊断。

精简文件统一metricColumns，各表values保留页面原字符串；nonExact保留缺失等例外状态，null不当零。保留账户合计/账户小时、链接日汇总/24小时、统计日/采集时刻/商品及推广ID、托管共享组和推导依据；不分摊花费、不计算利润。导出重新核对日期、身份、24小时与日汇总；未完成任务明确标记，不把未引用的历史数据补入当前任务。格式见GPT_EXPORT.md，测试见TESTING-v0.12.15.md。采集流程未改。


## v0.12.15 本机订单成本核算

展开“订单成本核算（本机）”。首次在“首次设置／更新成本”选择SKU成本XLSX/CSV、确认适用起始日期，保存到本机。以后只需填写上方店铺备注、导入订单CSV、选择并确认所属日期，点击核算。按日期选择适用成本版本；同一适用日期选最近导入的版本，旧核算记录保存当时逐单成本与版本。成本及订单不会放进源码、安装包或自动上传。

按SKU整套成本乘购买件数；取消/退款成功/售后处理中订单收入和成本均剔除；正常实收合计扣3.5%（合计四舍五入到分），再扣同日全部账户推广总花费，不重复加扣托管共享花费。缺成本、成本冲突、未知状态或缺同日推广数据时不输出完整经营结余。订单日期必须人工确认，不能从文件名推断。导出核算明细、本机成本版本备份/恢复及核算记录备份可用。详见ORDER_ACCOUNTING.md。旧采集/GPT导出保持。


## v0.12.15 商品／单链接核算明细

订单核算后新增商品明细表，按商品ID跨推广模式汇总一次，列出实收、整套SKU成本、手续费、扣广告前结余、已知推广花费和广告后结余。手续费对全店已取整金额做最大余数补分，保证商品合计回到全店。没有订单的推广商品也列出广告支出，防止遗漏。

同日账户商品明细必须通过日期/来源/合计/列表完整性核对。商品若参与托管共享费用，保留扣广告前结余和已知广告费，广告后结余显示“无法确定”，不擅自分摊。完整列表未见的商品只在所选推广报表范围内广告费记0。缺来源或不明花费差额时不宣称单链接利润。原全店核算口径、成本版本及采集/GPT导出不改；重新核算订单即可生成新明细，旧报告不覆盖。
